# Harness recapture

A maintainer reruns the real harness CLIs against a local model on one machine, and Skopli's readers are checked against what those CLIs write today, so provider binary drift shows up as a report instead of a silent miss.
One command owns the whole wave, and an agent only steps in when the run exits with a TODO, an unknown layout, changed auth or config, or a failed invariant.

## Sub-features

- `recapture-env` downloads llama.cpp `b11720` and `Qwen2.5-1.5B-Instruct` `q4_k_m` (exactly 1,117,320,736 bytes), clones the target project, starts `llama-server` and the usage gateway, and proves the cache counters rise on a second turn on both OpenAI Chat Completions and Anthropic Messages.
- `recapture-install` installs every harness a runnable cell needs into the cache (a pnpm home for packages, a separate HOME for vendor scripts) and writes `cli-versions.txt`.
- `recapture-run` runs each harness and wire-shape cell serially, with an isolated home, four turns, a 600 second budget per cell, and on Linux and macOS the process group of every turn killed by PID when the turn ends.
- `recapture-report` writes `cell-notes.<os>.tsv`, `matrix.<os>.md` and `drift.json`, and compares each cell with `golden/README.md`, the case directories under `golden/`, and an optional earlier run.
- `recapture-package` tars the run directory, without the copied target project, node modules or the runner's `tmp/`, for upload as one attachment.
- `recapture-lanes` tags every drift entry with a `lane` of `mechanical-candidate`, `decision` or `agent`, which the agent maps onto the three outcomes below.

## How to get to it (user POV)

- `node .agents/skills/verify-skopli/scripts/recapture.mjs all --out .verify/recapture/<utc-stamp>` runs the whole wave and always ends by stopping what it started.
- `node .agents/skills/verify-skopli/scripts/recapture.mjs list` prints every cell with its planned outcome on this OS.
- The steps `env`, `install`, `run`, `report`, `package` and `stop` run one at a time against the same `--out`.
  A failed or interrupted `all` or `env` stops the server and gateway only when that invocation got as far as starting them, so a pair an earlier `env` recorded is left alone, and an interrupt also kills the current turn and the run's strays: on Linux and macOS every process that carries its `RECAPTURE_TAG`, on Windows every process started since the invocation began from an executable under `--cache` or `--out`.
- `--only <harness>` or `--only <harness>/<shape>` (repeatable) selects a subset, `--os` plans for another OS with `list` or `--dry-run` only, `--resume` skips cells that already ran, and reruns those whose `result.json` is missing, says `error` or `not-installed`, or holds a skip or TODO the manifest no longer plans, `--baseline <dir>` adds CLI version changes against an earlier run on the same OS (a directory without that OS's report is a usage error), `--dry-run` prints the resolved plan as JSON, and `--timeout <s>` changes the per-cell budget, a whole number of seconds from 60 to 86400.
- Exit codes: `0` ran and found no new drift, `1` an invariant failed (download, byte size, a bound port, server or gateway readiness, cache proof, build, a crashed `home.mjs` or `reconcile.mjs`, a harness not installed, a planned cell with no result), `2` usage error, `3` new drift or a new TODO cell needs an agent.
  The cell outcomes (not installed, no result, drift, TODO) are judged by `report`, so a standalone `run` exits `0` once its cells have finished, and `all` exits with what `report` found.
- A run with TODO cells exits `3` until those cells are sourced, unless `--baseline` names a run whose `drift.json` already lists the same TODO, or the same `regressed` cell, with the same status and reason; such entries stay in `drift.json` with `"known": true` and do not count.
- The data lives in `recapture/harnesses.json` (install channel, store roots, per-shape commands, env, skip codes) and `recapture/seeds/<os>/<harness>-<shape>/` (the pre-run config files, written relative to the cell home with `{origin}`, `{home}` and `{cwd}` placeholders).
- `scripts/os-home.sh <cell-home>` prints the environment that points a harness at an isolated home on Linux, macOS or Windows, and `--plain` prints `NAME=value` lines for programs.

## Driving it with recapture.mjs

Preconditions:

- A Linux, macOS or Windows (Git Bash) machine with Node 24, pnpm, git, curl, tar, `uv` for trae, `which` on Linux and macOS and `ps` on macOS, network access to GitHub, Hugging Face and the npm registry, and about 3 GB free.
- No secrets: every cell uses the dummy key `sk-local` (or `local-only-placeholder` for Command Code), and the gateway accepts any key.
- Nothing else listening on ports 8090 and 8091; `env` refuses a bound port, and readiness only counts while the server and gateway it started are alive.

- **Plan.** Run `node .agents/skills/verify-skopli/scripts/recapture.mjs list`.
  Each line is `<harness>/<shape>`, then `run`, `skip:<code>` or `todo`, then for a `todo` the reason.
- **Environment.** Run `node .agents/skills/verify-skopli/scripts/recapture.mjs env --out .verify/recapture/<run>`.
  Stderr ends with `env: ok, server <pid>, gateway <pid>, cache proof passed`, and `cache-proof.json` shows `prompt_tokens_details.cached_tokens` and `cache_read_input_tokens` higher on turn two than on turn one.
  The step runs `pnpm install --frozen-lockfile` and `pnpm run build` first, because the readers run through the built facade.
  The llama.cpp archive comes from the fixed release asset URL `https://github.com/ggml-org/llama.cpp/releases/download/b11720/llama-b11720-bin-<asset>`, where `<asset>` is `ubuntu-x64.tar.gz`, `macos-arm64.tar.gz` or `win-cpu-x64.zip`, so no GitHub API call is made and its anonymous rate limit cannot fail the step.
  On Windows the zip is extracted with `%SystemRoot%\System32\tar.exe`, because the GNU tar that Git Bash puts first on PATH reads a drive-letter path as a remote host.
  The server runs with `-c 131072 -np 2 --rope-scaling yarn --rope-scale 2 --yarn-orig-ctx 32768 --alias qwen`, which gives each slot the 64K window Hermes requires.
  Windows adds `-n 1024` to cap each reply.
  macOS adds `-ngl 0`, because in a macOS VM the paravirtual Metal device generates about 1 token per second against about 70 on the CPU.
- **Install.** Run `node .agents/skills/verify-skopli/scripts/recapture.mjs install --out .verify/recapture/<run>`.
  `cli-versions.txt` has one line per harness: id, binary path, `MISSING` or `INSTALL-FAILED`, first line of `--version`; `--baseline` compares only the versions of harnesses installed in both runs.
  A `pnpm` channel runs `pnpm add -g --allow-build=<package>`, a `uv` channel runs `uv tool install` with the pinned Python and `--with` packages, and a `script` channel runs `curl -fsSL <url> | bash -s -- <args>`.
  Each install is bounded at 900 s and reported as `timed out after 900 s` when it hits the limit; a small node wrapper kills the installer's whole tree at the limit or on an interrupt (on Linux and macOS its process group, which also goes when the installer exits; on Windows `taskkill /T` while the leader lives), and the new processes that left the tree are killed afterwards, as described under the stray sweep below.
  As with timeout(1), an installer that itself exits 124 reads as a timeout.
  The installer's output goes to `<out>/install/<id>.log`, and an interrupt or a signal sent to the runner alone stops the whole step.
  Every install writes `<out>/install/<id>.failed` before the first one starts and removes it on success, so a failed, timed-out, interrupted, skipped or never-reached install leaves it, and `run` records that harness's cells as `not-installed` with the failure as the reason instead of testing a copy an earlier run left in `--cache`, so `report` raises an `invariant`, and `cli-versions.txt` lists it as `INSTALL-FAILED`.
  A script installer runs with HOME set to the script home inside `--cache` and with the harness's `install.env` added to its environment, for example `CONFIGURE=false`, which stops goose's installer from starting its interactive configuration.
  On Windows a `script` channel does not run; an `installOs.windows.ps1` channel runs `irm <url>` in PowerShell from the script home with its `args` and `env`, and a harness with neither plans as `todo` there.
  On macOS, launchd is per user rather than per HOME, so after each install the runner boots out any LaunchAgent whose plist that install wrote under the script home and that launchd loaded from that plist; an agent the operator loaded under the same label is left alone.
- **One cell.** Run `node .agents/skills/verify-skopli/scripts/recapture.mjs run --out .verify/recapture/<run> --only pi/openai-chat`.
  Stderr prints `pi/openai-chat: captured`, and `cells/pi/openai-chat/result.json` shows `"events": 4`, `"reconcileExit": 0` and `"detected": ["pi"]`.
- **Whole matrix.** Run `node .agents/skills/verify-skopli/scripts/recapture.mjs all --out .verify/recapture/<run>`.
  Cells run one at a time; the run takes hours on CPU inference.
- **Report.** Run `node .agents/skills/verify-skopli/scripts/recapture.mjs report --out .verify/recapture/<run> --baseline <earlier-run>`.
  Stdout is a JSON summary with status counts and the drift count, and the exit code is `0`, `1` or `3`.

The cell procedure the runner follows:

1. A rerun of a cell moves the earlier directory to `<shape>.attemptN` and starts with a fresh home; nothing resumes in place.
2. The target project is copied into `cells/<harness>/<shape>/work`, and the home is `cells/<harness>/<shape>/home` with the `os-home.sh` redirects applied.
3. The seed for this OS is copied into the home with placeholders filled; Linux and macOS seeds stand in for each other when the seed writes nothing under `Library/` or `AppData/`.
4. The runner checks that the server and gateway from `env` are still alive and that the server's `/health` and the gateway's `/v1/models` answer, and fails with exit `1` otherwise; it checks again after the turns, and a cell during which either died gets no `result.json`, so `--resume` runs it again.
5. An optional setup command runs (for example `cline auth openai ...`), then the four prompts in `harnesses.json` run, the first with `first` and the rest with `next`, sharing one `--timeout` budget, 600 seconds by default.
   A setup that times out makes the cell a `hang`, and a setup that exits non-zero skips the turns and records `setup exit N` as the reason.
6. A turn that outlives the budget is killed with its process group (`taskkill /T` by PID on Windows), and the turns after it are recorded as skipped.
7. The gateway log is sliced from the byte offset at cell start into `gateway-usage.jsonl`, without `aborted` lines, which are replies no harness received.
8. `home.mjs` writes `home-result.json`, and `reconcile.mjs` writes `reconcile.json` comparing Skopli's totals with the gateway's.
9. `result.json` records the status, turns, gateway lines, events, sessions, diagnostics, the store layout as path shapes, and the redaction needles found in the store.
   Only files the turns created or changed count, so seeds and setup output are not evidence, and the layout leaves out each harness's `layoutIgnore` subtrees, which hold logs or indexes the promoted golden cases do not keep.

Statuses in `result.json` and `cell-notes.<os>.tsv`:

| status           | meaning                                                                                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `captured`       | Skopli read events and they reconcile exactly with the gateway.                                                                                                                                               |
| `captured-delta` | Skopli read events but the totals differ from the gateway.                                                                                                                                                    |
| `reader-gap`     | Requests reached the gateway and the harness wrote its store, but Skopli read zero events.                                                                                                                    |
| `capture-gap`    | Setup exited non-zero, no request reached the gateway, or the harness wrote nothing under its store roots.                                                                                                    |
| `hang`           | Setup ran out the budget, or a turn did and Skopli read nothing.                                                                                                                                              |
| `error`          | `home.mjs` crashed or `reconcile.mjs` exited with something other than agreement or a delta; `report` then exits `1`.                                                                                         |
| `not-installed`  | The harness binary is not under `--cache` after the install step, its install failed, timed out, was interrupted or skipped (`install/<id>.failed`), or on Windows its `--version` probe failed or timed out. |
| `skip`           | The manifest says the cell cannot run; the reason is one of `gui-only`, `no-byok-endpoint`, `wrong-wire-shape`, `interactive-config`, `not-an-agent`.                                                         |
| `todo`           | The recovered kit could not source a field for this OS: the install channel, a command, or a config seed.                                                                                                     |

Run outputs, all under `--out` and never committed:

- `cell-notes.<os>.tsv`: three tab-separated columns, harness, shape, then free text that starts with the status and continues with the reason, gateway and event counts, store layout and redaction needles.
- `matrix.<os>.md`: one row per cell with status, detected harnesses, events, sessions, diagnostics, gateway lines, reconcile result, the `golden/README.md` status and the reason.
- `drift.json`: one entry per finding, each with a `kind` and a `lane`.
- `cli-versions.txt`, `install/<id>.log`, `install/<id>.failed`, `cache-proof.json`, `llama-server.txt`, `gateway-usage.jsonl`, `gateway-stderr.txt`, `state.json`, the run-scoped `tmp/`, and per cell `setup.txt`, `run-N.txt`, `gateway-usage.jsonl`, `home-read.json`, `home-result.json`, `reconcile.json`, `result.json`, the `work` directory the turns run in and the home itself.

Drift kinds and their lanes:

| kind               | when                                                                                             | lane                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| `newly-capturable` | A cell captured with no golden case for it.                                                      | decision                                                      |
| `unread-store`     | A cell with no golden case wrote its store and reached the gateway, but Skopli read zero events. | decision                                                      |
| `regressed`        | A cell with a golden case now ends in `capture-gap`, `reader-gap`, `hang` or `error`.            | `mechanical-candidate` for `reader-gap`, `decision` otherwise |
| `reconcile-delta`  | Skopli's totals differ from the gateway's.                                                       | decision                                                      |
| `layout-changed`   | The store holds path shapes the golden case does not.                                            | `mechanical-candidate`                                        |
| `version-changed`  | A CLI version differs from `--baseline`.                                                         | `mechanical-candidate`                                        |
| `todo`             | A cell could not be planned.                                                                     | agent                                                         |
| `invariant`        | A cell ended `error` or `not-installed`, or a planned cell has no result; `report` exits `1`.    | agent                                                         |

### The three lanes

`mechanical-candidate` entries end in the mechanical or the decision lane once the agent has checked them, and `agent` entries end in either after the agent has sourced the gap or fixed the environment.

- **No drift.** The run exits `0`; publish `matrix.<os>.md` and the package as the run's evidence, and open no product PR.
- **Mechanical drift.** The finding is version metadata, fixture bytes, or a known store path or schema adaptation, and exact reconciliation and every invariant still hold after the change.
  The scheduled session may change golden cases, readers or core code in its own implementation PR with before and after recapture evidence, independent review convergence, and the full CI and security checks.
  It may merge that PR only if branch policy allows it and zero findings remain.
- **Decision drift.** The finding is ambiguous or changed token semantics, a loss of authoritative usage, new auth, licensing or terms, an unsupported or new endpoint decision, or anything the scripts cannot establish as safe.
  Open a draft PR or an issue with the evidence if it helps, do not merge, and escalate to the user.
- A golden case is never rewritten just to turn a failing check green; a changed expectation needs a recapture that proves it.

### Agent judgment that is not scripted yet

- Choosing the lane for a `mechanical-candidate` entry: the script can say the layout or version changed, not whether the new layout carries the same token semantics.
- A `todo` cell: finding an install channel (the fx Windows installer) or a missing seed, then adding it to `harnesses.json` or `recapture/seeds/`.
- A changed auth flow or onboarding prompt, which shows up as `capture-gap` with a harness error in `run-N.txt`.
- Promotion with `promote.mjs`, because picking the redaction flags and writing the case README needs a reading of the captured store.
- Machine setup the scripts cannot do on every OS: `uv` must already be on `PATH` for Trae, and on Windows bun for omp and gajae and long paths enabled for the Hermes installer.

### Spawning the scheduled run

This section is the contract a scheduling orchestrator reads; it is the only place the platform list and the worker brief live.
The orchestrator runs this section on a cadence (every three weeks is the intended one), launches one cloud worker per platform from current `main`, and never runs the matrix itself.
Workers need no attachments and no secrets.

```text
platforms: linux, darwin, windows
```

The worker brief, with `<os>` set to the platform:

```text
Run the Skopli harness recapture on <os>.
Clone skopli/skopli at main; read AGENTS.md, CONTRIBUTING.md, .agents/skills/verify-skopli/SKILL.md and .agents/skills/verify-skopli/features/recapture.md before acting.
Run:
  node .agents/skills/verify-skopli/scripts/recapture.mjs all --out .verify/recapture/<utc-stamp> --baseline <previous run directory if you have it>
Run cells one at a time; never kill processes by name.
Attach the .tgz the package step prints and matrix.<os>.md to your final report; publish nothing unredacted (homes, credentials, machine paths, auth-gated URLs).
Exit 0: report no drift, open no PR, and stop.
Exit 1: read the failing step's stderr, fix the environment, and rerun the same command with --resume; open a focused runner PR only if repository code must change.
Exit 3: read drift.json and follow the three lanes above.
  Mechanical drift: change only the required reader, core behaviour, runner, seed or golden case; prove exact reconciliation; run pnpm run check; converge review on this VM with local subagents (never a new cloud session); settle CI; merge only if branch protection permits.
  Decision drift: open a draft PR or issue with the evidence, do not merge, and escalate.
Never rewrite a golden case only to make a check pass.
Keep generated runs, models, binaries, caches, isolated homes and node_modules out of git.
Fix minor issues autonomously; stop only for a product decision, a security concern or an unsafe blocker.
End with: exit code, cell counts by reason, cache-rise result, exact reconciliation examples, drift entries by lane, PR or issue links, review and CI results, and anything left unverified.
```

## Gotchas

- Run cells one at a time: four concurrent sessions saturated the 1.5B model on 8 cores and turned real captures into timeouts.
- Never stop a harness or server by process name; the runner kills only the PIDs and process groups it started, plus the strays below, and `stop` reads them from `state.json`.
- `env` records each server and gateway PID with its OS start time (the start in clock ticks from `/proc/<pid>/stat` on Linux, which a clock step cannot move, `ps -o lstart=` on macOS, the PowerShell `StartTime` of the process on Windows), and `stop` leaves a PID alone when its start time no longer matches, since the OS may have reused it.
  `stop` always clears the record and says which PIDs were already gone, which were not ours, and which it left running because their start time could not be read.
- A turn killed mid-flight leaves nothing in most stores, so a capture can report fewer turns than ran.
- Codex rejects `wire_api = "chat"`, Reasonix has no Responses shape, Command Code's Responses client never completes a stream against the gateway, and Trae's Chat Completions client crashes on a null `completion_tokens_details`; the last two still run so a fix upstream shows up as drift.
- Grok needs a real sign-in on macOS, so its cells skip there.
- Hermes refuses to start when the server advertises less than a 64K window, which is why the server uses YaRN scaling.
- On Windows Hermes ends its turns with `Gateway inaccessible: windows_breakaway_unavailable` even when spawned directly rather than through `cmd.exe`, so `hermes/openai-chat` records a `capture-gap` there (the message is in `run-N.txt`, and `result.json` says `no request reached the gateway`), which `--baseline` then carries as known; the likely cause is the job object of its vendor launcher, since `CREATE_BREAKAWAY_FROM_JOB` succeeded from Node and failed from Python under Git Bash on the proof host.
- fx writes a cumulative `set:usage` log, so its reader takes deltas; cline can leave orphaned host processes on macOS, which the runner kills with the turn's process group, or by the run's `RECAPTURE_TAG` in their environment when they started a session of their own.
- On Windows `taskkill /T` cannot walk the tree of a leader that already exited, so a turn's tree is killed on timeout, and after an exit only the processes started since the turn from an executable under `--cache` or `--out` are reaped; a stray hosted by the system `node.exe` (a pnpm `.cmd` shim) survives.
  A `--version` probe of a `.cmd` shim that times out leaves its `node.exe` child running the same way.
- After each install, turn and version probe the runner kills the strays that left the process group: on Linux and macOS every process that was not there before and carries this invocation's `RECAPTURE_TAG` in its environment, which every install, turn and probe sets, and on Windows, which has no such lookup, every process started since then from an executable under `--cache` or `--out`.
  So on Windows never share `--cache` between concurrent runs, and point `--out` at a dedicated run directory, or a process of another run would go too.
  Every installer gets `TEMP`, `TMP` and `TMPDIR` (not `TMPDIR` on macOS) under `<out>/tmp`, except a Windows `install.ps1`, which gets them inside the script home.
- Each cell's turns get `TEMP`, `TMP` and `TMPDIR` set to `<out>/tmp/<n>`, where `n` is the cell's position in this invocation's plan and the directory is emptied when the cell starts, and `--version` probes get `<out>/tmp`, so nothing a harness leaves there lands in the operator's temp dir; `package` leaves `<out>/tmp` out.
  The path is short because Linux allows 108 bytes for a socket path, and macOS keeps its per-user `TMPDIR`, because it allows only 104.
- On Windows, `os-home.sh` sets `USERPROFILE`, `APPDATA` and `LOCALAPPDATA` from `cygpath -w`; goose and Reasonix keep their stores under `APPDATA`, and mimocode follows the redirected home.
- Redact before promoting: the cell home and target paths, the username and hostname, the dummy keys, Windows 8.3 aliases such as `ADMINI~1`, PATH snapshots in Hermes `state_meta`, the origin remote's host (https, ssh or scp-style) when it is not github.com (a git proxy or mirror), and escaped Windows paths; `result.json` lists under `redaction` which needle kinds it found (`username`, `hostname`, `home-path`, `cell-home`, `cell-cwd`, `dummy-key`, `git-remote`, `8.3-alias`) in every native, forward-slash, MSYS and JSON-escaped spelling, scanning only the files the harness wrote under its store roots for this OS.
  A username of `user` or `root` is not scanned for, since `user` is a chat role in every store and `root` a common path word.
- A capture whose layout matches the Linux case is recorded as the same layout with its counts; only a differing layout becomes `golden/<harness>/<shape>-<os>/`, and the manifest keeps the shape name without the `-<os>` suffix.
- The pnpm home and the HOME that vendor install scripts see are both inside `--cache`, so a run never touches the machine's global packages or dotfiles, and the cache can be reused across runs.
- Cells never inherit `XDG_*`, `AWS_*`, `*_API_KEY`, `*_API_BASE`, `*_BASE_URL`, `*_TOKEN`, the store overrides `src/detect.ts` honours (`*_CONFIG_DIR`, `*_DATA_DIR`, `*_SESSIONS_DIR`, `*_SESSION_DIR`, `*_SESSION_DATA_DIR`, `*_AGENT_DIR`, `*_CODING_AGENT_DIR`, `CODEX_HOME`, `OPENCLAW_DIR`), `GOOGLE_APPLICATION_CREDENTIALS`, `ANTHROPIC_*`, `OPENAI_*`, `CLAUDE_CODE_*` (Bedrock and Vertex switches, model overrides), `NODE_OPTIONS`, any variable with a known harness prefix that redirects a store, a model or an endpoint (`CLINE_`, `CODEBUDDY_`, `COPILOT_`, `DEVIN_`, `DSH_`, `GJC_`, `GOOSE_`, `GROK_`, `HERMES_`, `JCODE_`, `KILO_`, `KIMI_`, `MIMOCODE_`, `MIMO_`, `OPENCODE_`, `PRIME_AGENT_`, `QWEN_`, `REASONIX_`), `UV_INSTALL_DIR` or `UV_UNMANAGED_INSTALL` from the parent environment, so a parent value cannot point a harness at the operator's real store, matched without regard to case because Windows variable names ignore case, and vendor installers do not see them either, nor a parent `VERSION` or `CANARY`, which the mimocode and goose installers read as a version pin and a release channel.
  Turns also drop `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY`, since they talk only to the local gateway; installs keep them.
- The package keeps every cell home unredacted, so attach it only to the private run report, never to a public PR or issue.
- On Windows a turn whose command resolves to a native `.exe` is spawned directly; any other command (a pnpm `.cmd` shim) runs through `cmd.exe` with every argument but a plain command name double-quoted, so a prompt must not contain `%`.
- On Windows an `installOs.windows.ps1` installer runs in PowerShell from the script home with a PATH of only the cache dirs, System32 and Git (installers scan PATH for an existing install).
  The bin dirs it adds to the user PATH in the registry move to `vendor-path.json` in `--cache`, which joins the run's PATH, and only those script-home entries are removed from the operator's user PATH, before and after each install keeping the registry kind and any other edits.
  The restored value keeps the pre-install entries in their order and appends an installer's entry only when no entry matches it without regard to case, so an installer that moves or re-adds an operator entry (jcode with an existing `%LOCALAPPDATA%\jcode\bin`) leaves the operator's PATH as it was.
  An operator entry gone after the install is reported on stderr rather than put back, since it cannot be told apart from an edit made meanwhile.
  The pre-install value is saved to `user-path-before.json` in `--cache` until the post-install restore succeeds, so an interrupted install is undone by the interrupt handler, or failing that at the start of the next `install` or by `stop`, entries an installer wrote back expanded against the script home get their `%VAR%` spelling back, and an install is skipped when the user PATH cannot be read or restored.
- jcode ignores `USERPROFILE` on Windows and resolves its store from `JCODE_HOME`, which the manifest points at `<cell home>/.jcode` for cells and at `<script home>/.jcode` for its installer, which runs `jcode.exe` itself (with `JCODE_SKIP_SERVER_RELOAD=1`).
- On Windows the run step probes each CLI with `--version` (reusing a successful install-step probe within one process, a failed one is retried), and a cell whose probe fails or times out is `not-installed`.
- An installer that adds a user PATH entry outside the script home is reported on stderr as `install <id>: left new user PATH entries outside the script home`; the check sees every entry that appeared during the install, so confirm the installer added it before removing it by hand.
- On Windows each turn also gets `PYTHONUTF8=1` and `PYTHONIOENCODING=utf-8`, so a Python CLI printing non-ASCII does not crash on the `cp1252` console code page.
