Skopli reads AI coding-agent usage (tokens, sessions, turns, calls) from local harness state, aggregates it, and prices it against market catalogs (OpenRouter, LiteLLM, models.dev). Every language calls into one Rust core, so the layers, options, and return shapes are the same everywhere. The TypeScript package is ESM only and needs Node 24 or newer.

Option keys follow each language's convention: `camelCase` in TypeScript, Java, and Swift (`cacheDir`, `ttlMs`), `PascalCase` in C# and Go (`CacheDir`, `TtlMs`), `snake_case` in Python, Ruby, and Rust (`cache_dir`, `ttl_ms`), and JSON keys in the C ABI.
The semantics are the same in every language, and only the spelling changes.
Each section's table describes an option once, and the tabs show the per-language spelling.

## Layers

### 1. Read (offline)

`detectHarnesses` reports which harnesses have local data. `readUsage` parses that data into normalized `UsageEvent`s and returns `{ events, diagnostics, skipped }`. It never touches the network.

<Tabs syncKey="lang">
  <Tab label="TypeScript">
    ```ts
    detectHarnesses(): { supported, unsupported };

    readUsage(options?: {
      harnesses?: string[];   // default: all detected
      since?: string;         // inclusive lower bound
      until?: string;         // exclusive upper bound
      tz?: string;            // timezone for date-only bounds
      subagents?: "include" | "exclude"; // default "include"
      home?: string;          // optional PathResolver injection
      env?: Record<string, string>;
    }): Promise<{
      events: UsageEvent[];
      diagnostics: Diagnostic[];
      skipped: Skipped[];
    }>;
    ```

  </Tab>
  <Tab label="Python">
    ```python

        harnesses=None,        # list[str] | None; default: all detected

        home=None,             # optional PathResolver injection
        env=None,              # dict[str, str] | None
    ```

The return shape is the same across languages. Python, Ruby, and Rust use `snake_case` field names. The C ABI JSON keeps the camelCase wire keys shown below, for example `cacheRead`, `cacheWrite1h`, `costUsd`, and `fetchedAt`. `UsageEvent`:

```ts
{
  harness,
  timestamp,
  sessionId,
  messageId,
  turn,
  subagent,
  model,
  tokens: { input, output, cacheRead, cacheWrite, cacheWrite1h?, reasoning },
  calls?,
  costUsd?,
  workspace?,
  title?,
}
```

- `cacheWrite` is the total. `cacheWrite1h` is the 1h-TTL portion when the source reports the split (Claude Code).
- `costUsd` is the harness-recorded cost (Claude Code JSONL `costUSD`, OpenCode nonzero `cost`), absent otherwise.
- `workspace` (normalized project dir, cross-platform: forward slashes, no trailing sep, case-folded on Windows) and `title` come from the OpenCode session directory and title and from Claude Code `cwd`, absent otherwise.
- Subagent (child-session or sidechain) events are included and tagged `subagent: true` by default, and `subagents: "exclude"` drops them uniformly.
  [Reading usage](/skopli/guide/reading#subagents) lists each harness's marker.
- The SDK never writes to stdio. Problems are structured diagnostics.

See [Reading usage](/skopli/guide/reading) for the full guide.

### 2. Rollup (offline)

`rollup` groups events by `model`, `day`, `session`, `harness`, `workspace`, or `block` and returns a sorted `Rollup[]`. It never touches the network.

    ```ts
        by: "model" | "day" | "session" | "harness" | "workspace" | "block";
        tz?: string;
        // block width for by: "block" (default 18000000)
        blockMs?: number;

    ): Rollup[];
    ```

Each `Rollup` has summed tokens, events, turns, calls, and `costUsd` (summed recorded cost, present only when an event carried one). Workspace bucketing folds events without a workspace under the `"(unknown)"` sentinel.

`by: "block"` groups events into rolling session windows that approximate a provider usage-quota window, for example Claude subscription five-hour blocks.
The window is derived from your own events, so the provider's own accounting can differ.

- A block opens at the first event floored to the hour in `tz` and spans `blockMs` (default `18000000`, five hours).
- Events in `[start, start + blockMs)` join it.
- The first event at or past `start + blockMs` opens a new block.
- Each row's `key` is the ISO-8601 block-start instant, and rows come back in ascending start order.
- The library never reads the clock. Flag the still-open block caller-side by comparing its `end` (`start + blockMs`) against the current time.

The `tz` option buckets days in an IANA timezone on every rollup path, DST transitions and sub-hour offsets included.
The TypeScript implementation formats each timestamp with `Intl.DateTimeFormat` under `timeZone: tz`, and the native core (`skopli-core`) with every facade that calls it (Python, Ruby, Java, C#, Go, Swift, and the C ABI) produces the same buckets.
A day rollup therefore agrees with a `tz`-scoped `since` and `until` filter east or west of UTC.
An unknown zone name falls back to UTC.

See [Rollups](/skopli/guide/rollups).

### 3. Price (network by default, cached)

The Price layer is the only layer that touches the network. It fetches market catalogs by default when used, caches them, and reads from cache when offline. An empty `sources` list or `offline` makes it network-free. Every facade exposes the same operations.

#### 3a. Pricing constructor

The seven handle-based facades (TypeScript, Python, Ruby, Java, C#, Go, Swift) construct a full pricing handle with `createPricing`.
The FFI facades (Java, C#, Go, Swift) run the fetch in the host language and hand pre-fetched catalogs to the network-free `libskopli`.
Those handles are closeable.
Rust exposes the pricing primitives directly and has no constructor.
The bare C ABI's `ag_pricing_new` takes injected `catalogs` (or overrides) in its options JSON.
The default `libskopli` fetches nothing, and built-in sources require the `net` build (`libskopli-full`).

Key spelling follows the language (`cacheDir` and `cache_dir`, `ttlMs` and `ttl_ms`, `PricingMode.Calculate`, `"calculate"`, and `.calculate`). Use `catalogs` to hand in pre-fetched catalogs, or `sources` plus `fetch` to drive the built-in fetch lifecycle.

| Option      | Meaning                                                                                                                                                                      |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sources`   | Catalog sources in priority order. Default: OpenRouter, LiteLLM, models.dev. Available on all seven handle facades; in TypeScript it also stands in for explicit `catalogs`. |
| `catalogs`  | Explicit pre-fetched catalogs, in priority order after overrides. Every facade except TypeScript accepts it.                                                                 |
| `overrides` | Your own rates. Highest priority, beats every market source. An explicit `$0` counts.                                                                                        |
| `mode`      | `calculate` (default), `display`, or `auto`. See below.                                                                                                                      |
| `cacheDir`  | Disk cache location. Default: the platform cache dir.                                                                                                                        |
| `offline`   | Read cache only, never fetch.                                                                                                                                                |
| `ttlMs`     | Cache freshness window.                                                                                                                                                      |
| `refresh`   | Attempt one fresh fetch per source, bypassing fresh caches. Stale cache is still used on failure.                                                                            |
| `fetch`     | Injectable getter for the built-in sources, for tests and proxies. On all seven handle facades.                                                                              |

Priority runs overrides, then explicit catalogs, OpenRouter, LiteLLM, and models.dev, with one exception for tiered matches described under [Source priority](/skopli/pricing/model-matching#source-priority).

**`mode`** picks each priced row's `usd`: `calculate` recomputes from tokens, `display` uses the recorded cost or `0`, `auto` prefers recorded then calculated.

#### 3b. lookupModel and priceTokens

`lookupModel` matches a model name against the loaded catalogs and returns a `PriceHit` or a miss.
`priceTokens` prices a token bundle at a resolved price.
`lookupModel` belongs to every pricing handle.
In Rust it is a method on `Pricing` (`pricing.lookup_model(model)`), and `cost_usd` is a free function that prices a token bundle at a `ModelPrice`.
`priceTokens` is a convenience on the TypeScript, Python, and Ruby handles.
The FFI facades cover it through `priceRollups` and `priceEvents`, which match and price in one call.

<Tabs syncKey="lang">
  <Tab label="TypeScript">

#### 3c. priceRollups

`priceRollups(rollups)` prices already-summed tokens.
It is exact for flat-rate models.
For a tiered model, a rollup that aggregated more than one event (or a single event with `calls > 1`) can cross a tier the individual calls never reached, and the row overbills.
Skopli flags that row with `pricing.tieredAggregate: true` (calculate mode, or auto without a recorded cost).

`priceRollups` is on every pricing handle. `priceEvents` prices each event at its own context, which is what tiered models need. See [Price rollups or raw events](/skopli/pricing/rollups-vs-events).

#### 3e. catalogs and cache

Each source caches on disk with a 1-hour TTL and atomic writes, and a stale cache at any age serves when a fetch fails.
`refresh: true` attempts one fresh fetch per source, bypassing fresh caches and falling back to stale on failure. Default fetches abort after 10s. Results carry source attribution and `fetchedAt`. Prices are USD per million tokens.

`catalogs()` reports the loaded sources (source, `fetchedAt`, model count), so you can tell when every market source failed and lookups can only miss. It is on every pricing handle that has one (`catalogs` in TypeScript, Python, and Ruby, `Catalogs()` in Java, C#, and Go, and `catalogs()` in Swift). In Rust the equivalent is `Pricing::catalog_infos`, which reports the catalogs you injected.

See [Pricing basics](/skopli/guide/pricing-basics) and [Model matching](/skopli/pricing/model-matching).

## Diagnostics and error shapes

The SDK never writes to stdio. Problems come back as structured values, and unmatched models come back as misses.

- `diagnostics` lists malformed lines, unreadable files, and unusable timestamps from the Read layer, and `skipped` lists the source files skipped per harness. `readUsage` returns both alongside `events`.
- `lookupModel` and a group in `priceEvents`/`priceRollups` return `{ priced: false, attempted }` (the model keys tried) when no rate is found, or `{ priced: false, reason: "zeroCost", key }` when only zero-cost placeholders matched.
- `tieredAggregate: true` marks a priced row where summed context may have crossed a tier boundary the individual calls never reached (see 3c and 3d).
- Every C ABI `ag_*` call returns an `AgStatus`. `AG_STATUS_OK` means the `AgBuf` holds a JSON result to read and then free with `ag_buf_free`. Non-OK statuses carry the error rather than writing to stdio.

These shapes are the same across languages, in each language's field-name convention. Python, Ruby, and Rust use `fetched_at`. Every other facade uses `fetchedAt`, the C ABI JSON wire keys included.

## Model matching

Matching runs in tiers, from the exact key through a provider-prefix strip, family aliases, separator and date-stamp normalization, and provider-prefixed family forms, to a hand-maintained alias table for names the mechanical tiers miss.

A miss returns `{ priced: false, attempted }`. Zero-cost catalog entries count as placeholders and skip, so matching falls through to the next source. When only zero-cost entries match, the result is `{ priced: false, reason: "zeroCost", key }`. An explicit `$0` in `overrides` is honored as a real price, not skipped.

See [Model matching](/skopli/pricing/model-matching).

## Semantics

- Date-only since and until strings (`YYYY-MM-DD`) are interpreted in `tz` (default: system timezone): since = start of day, until = exclusive end of day.
  Full ISO timestamps apply exactly as given.
  West of UTC this matters for filtering: with `tz America/Los_Angeles`, since `"2026-08-01"` excludes an event at `2026-08-01T00:30Z` (17:30 Jul 31 local).
  Day rollups bucket in the same `tz` on every path, so a day rollup never shows a `"2026-07-31"` row and filtering and day rollups agree at the UTC boundary across all SDKs (an unknown zone name falls back to UTC).
- The reader drops zero-token rows regardless of vendor-reported cost.
- Unusable timestamps produce a warning and skip the row.
- `calls` aggregation uses the reported count only when finite, else 1 per event.
- Reasoning tokens bill as output, cache rates fall back to the input rate when a catalog omits them, and 1h cache writes bill at their own rate.
  See [Price tokens and cache writes](/skopli/pricing/cost-math).
- Codex CLI, Grok Build, and ZCode report reasoning inside their output count, so the reader subtracts reasoning from output.
  GitHub Copilot CLI is the documented exception; see [Price tokens and cache writes](/skopli/pricing/cost-math#base-cost-math).
- Codex CLI cache-write tokens come from `cache_write_input_tokens` (a 2026-07 protocol addition), a disjoint subset of `input_tokens` like cache reads, so the reader subtracts them from input (`input = raw_input - cacheRead - cacheWrite`) and emits them as `tokens.cacheWrite`. Older session files that lack the field count as 0.
- Long-context tiers (LiteLLM only) are chosen by total context (`input + cacheRead + cacheWrite`), marginal by default and whole-request for `claude` model keys.
  See [Long-context tiers](/skopli/pricing/long-context-tiers).
- Cross-store dedup: the authoritative store suppresses its mirror per harness (OpenCode and ZCode SQLite over JSONL, Devin CLI SQLite over the Desktop `.ndjson` store, the Cline extension store over its CLI session store, the DeepSeek Harness default JSONL event log over its optional SQLite backend, keyed on `session_id` and `seq`).
