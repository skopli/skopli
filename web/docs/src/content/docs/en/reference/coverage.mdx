---
title: Coverage
description: What Skopli reads today, and the tools it cannot read locally yet with the reason for each.
---

Skopli reads local session state from 40 coding agents. See [Supported harnesses](/skopli/reference/harnesses) for the full list and their ids.

Some agents keep their token data cloud-side, store it without token counts, or have no stable local file to read. Skopli cannot read those locally today. The reason differs per tool, so each is listed below.

## Tools not readable locally yet

| Tool            | Why it is not readable locally                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Cursor          | Token usage is only available in the vendor dashboard, not on disk.                                                                   |
| Warp            | The local database stores conversations but no token counts.                                                                          |
| MiniMax Code    | The desktop app has no documented local file or schema for token counts. Diagnostics are uploaded to the vendor.                      |
| Synthetic       | The local database stores session history but no provider token counts.                                                               |
| Freebuff        | Local files store messages only. Token usage is credit-based and fetched from the vendor.                                             |
| Antigravity     | Token usage is quota-based and shown in a dashboard. No documented local usage-log path or token schema is available.                 |
| Antigravity CLI | No documented local file records provider token counts.                                                                               |
| Sakana Fugu     | A hosted model API rather than a local agent, so no session or token data is stored on disk.                                          |
| Senpi           | No local file records provider token counts.                                                                                          |
| WorkBuddy       | No local file records provider token counts.                                                                                          |
| Trae IDE        | The IDE keeps token usage quota-based in a dashboard, with no documented local token file or schema. The trae-agent CLI is supported. |
| aider           | Detected from its `.aider*` files in the home directory, but no local file with provider token counts is read, so there is no usage.  |
| Crush           | Usage files are project-local with no stable discovery location.                                                                      |
| GitLab Duo CLI  | Sessions are kept server-side as GraphQL checkpoints. The only local artifact is a prompt-history file with no token counts.          |

This list changes as tools ship durable local token logs. When a tool starts recording provider token counts in a stable local file, it moves to the supported list.
