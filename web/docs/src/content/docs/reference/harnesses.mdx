[^reasonix-session]: Reasonix persists only a per-session cumulative usage total (in the session's `.acp.json` metadata sidecar), so it reports one event per session, not one per turn. Sessions whose totals are marked estimated are still included.

[^kiro-estimated]: Kiro CLI persists full conversation text but no provider token counts, so its token counts are estimated from the stored message length (about four characters per token). Treat Kiro totals as estimates, not billed usage.

[^fx-aggregate]: fx.sh persists real provider token counts per session in a `usage-v2.json` sidecar, aggregated per model rather than per turn, so it reports one event per model per session. Every session is read regardless of its billing state; the recorded counts are the applied totals in all states.

## Detected but unsupported

These are detected but have no reliable local token data: **Cursor, aider, Crush, GitLab Duo CLI**.

`detectHarnesses()` reports them separately so you can tell users why they are missing.
