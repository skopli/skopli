import { Tabs, TabItem } from "@astrojs/starlight/components";

Skopli reads AI coding-agent usage (tokens, sessions, turns, calls) from local harness state, aggregates it, and prices it against market catalogs (OpenRouter, LiteLLM, models.dev). Every language calls into one Rust core, so the layers, options, and return shapes are the same everywhere. Only naming conventions differ. TypeScript, Java, C#, and Swift use camelCase. Python, Ruby, and Rust use snake_case. C# and Go use PascalCase methods. C uses a JSON-buffer ABI. The TypeScript package is ESM only and requires Node >= 24.

:::note[Full pricing parity across every facade]
The Read, Rollup, and Price layers expose the same operations and return shapes in every language. The seven handle-based facades (TypeScript, Python, Ruby, Java, C#, Go, Swift) each expose the full pricing set: `createPricing`, plus `lookupModel`, `priceRollups`, `priceEvents`, and `catalogs`. `priceTokens` is a convenience on the TypeScript, Python, and Ruby handles. The others cover it through `priceRollups` and `priceEvents`. The constructor options are shared but not byte-identical: the other six facades (Python, Ruby, Java, C#, Go, Swift) accept explicit pre-fetched `catalogs`, while TypeScript covers the same need through its `sources` plus an injectable `fetch`. Those seven run the same built-in fetch and cache lifecycle: sources on by default in priority order OpenRouter, LiteLLM, models.dev, a byte-compatible disk cache, and TTL, refresh, offline, and stale-fallback. In the FFI ones (Java, C#, Go, Swift) the fetch runs facade-side, since the embedded `libskopli` opens no socket by default. Rust (`skopli-core`) has no `createPricing`: you build a `Pricing` from injected catalogs and call `lookup_model`, `price_rollups`, or `price_events`, with `cost_usd` and `match_model` as lower-level free functions. The bare C ABI has no host lifecycle: the default `libskopli` prices against the pre-fetched `catalogs` you pass to `ag_pricing_new`, and built-in sources return an error unless the library is built with `net` as `libskopli-full`.
:::

Option keys follow each language's convention: `camelCase` in TypeScript, Java, C#, and Swift (`cacheDir`, `ttlMs`), `snake_case` in Python, Ruby, and Rust (`cache_dir`, `ttl_ms`), and JSON keys in the C ABI. The semantics are identical, only the spelling changes. Each section's table describes an option once, and the tabs show the per-language spelling.

## Layers

### 1. Read (offline)

`detectHarnesses` reports which harnesses have local data. `readUsage` parses that data into normalized `UsageEvent`s and returns `{ events, diagnostics, skipped }`. It never touches the network.

The return shape is the same across languages. Python, Ruby, and Rust use `snake_case` field names. The C ABI JSON keeps the camelCase wire keys shown below, for example `cacheRead`, `cacheWrite1h`, `costUsd`, and `fetchedAt`. `UsageEvent`:

```ts
{
  harness,
  timestamp,
  sessionId,
  messageId,
  turn,
  subagent,
  model,
  tokens: { input, output, cacheRead, cacheWrite, cacheWrite1h?, reasoning },
  calls?,
  costUsd?,
  workspace?,
  title?,
}
```

- `cacheWrite` is the total. `cacheWrite1h` is the 1h-TTL portion when the source reports the split (claude).
- `costUsd` is the harness-recorded cost (claude jsonl `costUSD`, OpenCode nonzero `cost`), absent otherwise.
- `workspace` (normalized project dir, cross-platform: forward slashes, no trailing sep, case-folded on Windows) and `title` come from the OpenCode session directory and title and from claude `cwd`, absent otherwise.
- Subagent (child-session or sidechain) events are included and tagged `subagent: true` by default. `subagents: "exclude"` drops them uniformly. `subagent` is set from each harness's native marker: OpenCode non-null `parent_id` or `parentID`, claude strict `isSidechain === true`, pi and omp `rlmDepth > 0`, deepseek a parent session, `origin` of `subagent`, or delegation depth above 0 (both the JSONL and SQLite backends), codex and all other harnesses always `false`.
- The SDK never writes to stdio. Problems are structured diagnostics.

See [Reading usage](/skopli/guide/reading/) for the full guide.

Each `Rollup` has summed tokens, events, turns, calls, and `costUsd` (summed recorded cost, present only when an event carried one). Workspace bucketing folds events without a workspace under the `"(unknown)"` sentinel.

`by: "block"` groups events into rolling session windows that approximate a provider usage-quota window, for example Claude subscription five-hour blocks. It is a convenience view of your own recorded usage, not official provider accounting. A block opens at the first event floored to the hour in `tz` and spans `blockMs` (default `18000000`, five hours). Events in `[start, start + blockMs)` join it, and the first event at or past `start + blockMs` opens a new block. Each row's `key` is the ISO-8601 block-start instant, and rows come back in ascending start order. The library never reads the clock, so flag the still-open block by comparing its `end` (`start + blockMs`) against the current time caller-side.

The `tz` option buckets days in an IANA timezone on every rollup path. The TypeScript implementation formats each timestamp with `Intl.DateTimeFormat` under `timeZone: tz` (`src/rollup.ts`). The native core (`skopli-core`) and every facade that calls it (Python, Ruby, Java, C#, Go, Swift, and the C ABI) bucket days in the same zone, DST transitions and sub-hour offsets included, so all paths agree bucket for bucket. A non-UTC `tz` shifts the day boundary consistently, so a day rollup agrees with a `tz`-scoped `since` and `until` filter east or west of UTC. An unknown zone name falls back to UTC.

See [Rollups](/skopli/guide/rollups/).

### 3. Price (network, opt-in)

The Price layer is the only layer that touches the network, and only when you opt in. It fetches catalogs, caches them, and reads from cache when offline. Every facade exposes the same operations.

#### 3a. Pricing constructor

The seven handle-based facades (TypeScript, Python, Ruby, Java, C#, Go, Swift) construct a full pricing handle with `createPricing`. The FFI ones (Java, C#, Go, Swift) run the fetch facade-side in the host language and hand pre-fetched catalogs to the network-free `libskopli`. Those handles are closeable. Rust exposes the pricing primitives directly and has no constructor. The bare C ABI's `ag_pricing_new` takes injected `catalogs` (or overrides) in its options JSON. The default `libskopli` fetches nothing, and built-in sources require the `net` build (`libskopli-full`).

The options carry the same semantics in every language, only the key spelling changes (`cacheDir`/`cache_dir`, `ttlMs`/`ttl_ms`, `PricingMode.Calculate`/`"calculate"`/`.calculate`). One option differs by facade: `catalogs` is accepted by the six non-TypeScript handle facades (Python, Ruby, Java, C#, Go, Swift) and the C ABI, while TypeScript covers the same need through `sources`. `sources` and `fetch` are on all seven handle facades. Use `catalogs` to hand in pre-fetched catalogs, or `sources` plus `fetch` to drive the built-in fetch lifecycle.

| Option      | Meaning                                                                                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sources`   | Catalog sources in priority order. Default: OpenRouter, LiteLLM, models.dev. On all seven handle facades, the TypeScript-side alternative to explicit `catalogs`. |
| `catalogs`  | Explicit pre-fetched catalogs, in priority order after overrides. (All facades except TypeScript.)                                                                |
| `overrides` | Your own rates. Highest priority, beats every market source. An explicit `$0` counts.                                                                             |
| `mode`      | `calculate` (default), `display`, or `auto`. See below.                                                                                                           |
| `cacheDir`  | Disk cache location. Default: the platform cache dir.                                                                                                             |
| `offline`   | Read cache only, never fetch.                                                                                                                                     |
| `ttlMs`     | Cache freshness window.                                                                                                                                           |
| `refresh`   | Attempt one fresh fetch per source, bypassing fresh caches. Stale cache is still used on failure.                                                                 |
| `fetch`     | Injectable getter for the built-in sources, for tests and proxies. On all seven handle facades.                                                                   |

**Priority:** overrides > explicit catalogs > OpenRouter > LiteLLM > models.dev, with one exception. After overrides, any tier-bearing match outranks a flat (tier-less) match from a higher-priority source, so long-context tiers are not lost to a higher-priority flat source (in practice, tiered LiteLLM beating flat OpenRouter).

**`mode`** picks each priced row's `usd`: `calculate` recomputes from tokens, `display` uses the recorded cost or `0`, `auto` prefers recorded then calculated.

#### 3b. lookupModel and priceTokens

`lookupModel` matches a model name against the loaded catalogs and returns a `PriceHit` or a miss. `priceTokens` prices a token bundle at a resolved price. `lookupModel` belongs to every pricing handle. In Rust it is a method on `Pricing` (`pricing.lookup_model(model)`), and `cost_usd` is a free function that prices a token bundle at a `ModelPrice`. `priceTokens` is a convenience on the TypeScript, Python, and Ruby handles (Rust uses `cost_usd`). The FFI facades cover it through `priceRollups` and `priceEvents`, which match and price in one call.

#### 3c. priceRollups

`priceRollups(rollups)` prices already-summed tokens. It is exact for flat-rate models. For a tiered model whose rollup aggregated more than one event (or a single event that itself aggregates multiple calls, `calls > 1`), the summed context can cross a tier the individual calls never reached, overbilling. That row is flagged `pricing.tieredAggregate: true` (calculate mode, or auto without a recorded cost), so it is never a silent misprice.

`priceRollups` is on every pricing handle. For tiered models, prefer `priceEvents`, which prices each event at its own context.

#### 3e. catalogs and cache

Per-source disk cache (~1h TTL, atomic writes, stale fallback at any age). `refresh: true` attempts one fresh fetch per source, bypassing fresh caches, falling back to stale on failure. Default fetches abort after 10s. Results carry source attribution and `fetchedAt`. Prices are USD per million tokens.

`catalogs()` reports the loaded sources (source, `fetchedAt`, model count), so you can tell when every market source failed and lookups can only miss. It is on every pricing handle that has one (`catalogs` in TypeScript/Python/Ruby, `Catalogs()` in Java/C#/Go, `catalogs()` in Swift). In Rust the equivalent is `Pricing::catalog_infos`, which reports the catalogs you injected.

See [Pricing basics](/skopli/guide/pricing-basics/) and the [pricing deep dive](/skopli/pricing/model-matching/).

## Diagnostics and error shapes

The SDK never writes to stdio. Problems come back as structured values, and unmatched models as misses, never guesses.

- **`diagnostics`**: malformed lines, unreadable files, and unusable timestamps from the Read layer. **`skipped`**: source files skipped per harness. Both are returned alongside `events` from `readUsage`.
- **Pricing misses**: `lookupModel` and a group in `priceEvents`/`priceRollups` return `{ priced: false, attempted }` (the sources tried) when no rate is found, or `{ priced: false, reason: "zeroCost", key }` when only zero-cost placeholders matched.
- **`tieredAggregate: true`**: a priced row where summed context may have crossed a tier boundary the individual calls never reached (see 3c and 3d).
- **C ABI status**: every `ag_*` call returns an `AgStatus`. `AG_STATUS_OK` means the `AgBuf` holds a JSON result to read and then free with `ag_buf_free`. Non-OK statuses carry the error rather than writing to stdio.

These shapes are the same across languages, in each language's field-name convention. Python, Ruby, and Rust use `fetched_at`. Every other facade uses `fetchedAt`, the C ABI JSON wire keys included.

## Model matching

Tiered: exact → provider-prefix strip (`openai/gpt-5` → `gpt-5`) → family aliases (some platforms carry a model line under their own route prefix, for example Amazon Bedrock's cross-region `us.anthropic.claude-opus-4-6-20260115-v1:0` → `claude-opus-4.6`, so those names price as the underlying Claude model) → separator and date-stamp normalization (`claude-sonnet-4.5` ~ `claude-sonnet-4-5` ~ `claude-sonnet-4-5-20250929`) → provider-prefixed family forms (`claude-opus-4.6` → `anthropic/claude-opus-4.6`, how OpenRouter keys Claude) → alias table (hand-maintained, for names the mechanical tiers miss).

A miss returns `{ priced: false, attempted }` instead of a guess. Zero-cost catalog entries count as placeholders and skip, so matching falls through to the next source. When only zero-cost entries match, the result is `{ priced: false, reason: "zeroCost", key }`. An explicit `$0` in `overrides` is honored as a real price, not skipped.

See [Model matching](/skopli/pricing/model-matching/).

## Semantics

- Date-only since and until strings (`YYYY-MM-DD`) are interpreted in `tz` (default: system timezone): since = start of day, until = exclusive end of day. Full ISO timestamps apply exactly as given. West of UTC this matters for filtering: with `tz America/Los_Angeles`, since `"2026-08-01"` excludes an event at `2026-08-01T00:30Z` (17:30 Jul 31 local). Day rollups bucket in the same `tz` on every path, so a day rollup never shows a `"2026-07-31"` row and filtering and day rollups agree at the UTC boundary across all SDKs (an unknown zone name falls back to UTC).
- The reader drops zero-token rows regardless of vendor-reported cost.
- Unusable timestamps warn and skip, never epoch-0.
- `calls` aggregation uses the reported count only when finite, else 1 per event.
- Reasoning tokens bill as output. Cache price tiers fall back to the input rate when a catalog omits them.
- Codex, Grok, and ZCode report reasoning inside their output count, so the reader subtracts reasoning from output (`output + reasoning` reconstructs the source's raw output). Copilot OTel is the deliberate exception: the OTel GenAI conventions do not state whether `output_tokens` includes reasoning, so the reader assumes they are disjoint and does not subtract. If Copilot output turns out to be reasoning-inclusive, its reasoning would be double-billed.
- Codex cache-write tokens come from `cache_write_input_tokens` (a 2026-07 protocol addition), a disjoint subset of `input_tokens` like cache reads, so the reader subtracts them from input (`input = raw_input - cacheRead - cacheWrite`) and emits them as `tokens.cacheWrite`. Older session files that lack the field count as 0.
- 1h cache writes (`tokens.cacheWrite1h`) bill at the catalog above-1hr rate (LiteLLM `cache_creation_input_token_cost_above_1hr`) when present, else input × 2.0. The rest of cacheWrite bills at the base cacheWrite rate. Source priority is per-model, not per-field.
- Long-context tiers (LiteLLM only): the tier is chosen by total context (`input + cacheRead + cacheWrite`), with marginal billing by default and whole-request repricing for claude models. The cacheWrite 5m/1h split composes per tier: the 1h portion bills at the selected level's 1h rate, the 5m remainder at its cacheWrite rate.
- Cross-store dedup: the authoritative store suppresses its mirror per harness (OpenCode and zcode sqlite over jsonl, devin CLI sqlite over the Desktop `.ndjson` store, cline's extension store over its CLI session store, deepseek's default JSONL event log over its optional SQLite backend, keyed on `session_id` and `seq`).
