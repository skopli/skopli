## Date and timezone semantics

`tz` interprets date-only `since` and `until` strings (`YYYY-MM-DD`). It defaults to the system timezone. `since` means midnight at the start of that day. `until` means the exclusive end of that day.

Full ISO timestamps apply exactly as given.

This keeps filters and day rollups consistent west of UTC. With `tz: "America/Los_Angeles"`, `since: "2026-08-01"` excludes an event at `2026-08-01T00:30Z` (17:30 on Jul 31 in Los Angeles), and the day rollup buckets that event under Jul 31 local, so the two agree.

The native core buckets rollup days in the same IANA timezone on every path (see [Rollups](/skopli/guide/rollups/)), so a `tz`-scoped filter and a `tz` day rollup agree at the UTC boundary in every SDK. An unknown zone name falls back to UTC.

## Event fields

Every event carries:

- `harness`: the harness id.
- `timestamp`: ISO timestamp.
- `sessionId`, `messageId`.
- `turn`: turn flag.
- `subagent`: subagent flag (see [Subagents](#subagents)).
- `model`: model name.
- `tokens`: token counts. `input`, `output`, `cacheRead`, `cacheWrite`, optional `cacheWrite1h` (the 1h-TTL portion of the `cacheWrite` total when the source reports the split), and `reasoning`.
- `calls`: optional count for sources that aggregate multiple model calls per record.
- `costUsd`: optional harness-recorded cost when the source reports one. The Claude reader populates it from the jsonl `costUSD` field. The OpenCode reader populates it from a nonzero `cost`. Other readers leave it absent.
- `workspace`: optional normalized project directory path. OpenCode records it from its session directory, Claude Code from each record's `cwd`. Readers without the concept leave it undefined. Workspace paths are normalized cross-platform (forward slashes, no trailing separator, case-folded on Windows) so one repository is one key.
- `title`: optional session title. OpenCode records it from its session title. Readers without the concept leave it undefined.

:::tip[Disjoint token buckets]
`cacheWrite1h` is a portion of the `cacheWrite` total, not additive to it. Readers subtract reasoning-inclusive output at the source, so `output + reasoning` reconstructs the source's raw output count and nothing bills twice.
:::

## Subagents

Subagent (child) sessions are real spend, so Skopli includes and tags them by default rather than dropping them. Pass `subagents: "exclude"` to drop them uniformly across every harness.

`event.subagent` is `true` when the harness's native marker says the event came from a subagent:

- **OpenCode**: the session has a non-null `parent_id` or `parentID` (SQLite and legacy JSON stores).
- **claude**: the JSONL entry has `isSidechain === true`.
- **pi** and **omp**: the session's `rlmDepth` is greater than 0.
- **deepseek**: the session has a parent session, an `origin` of `subagent`, or a delegation depth above 0 (both the JSONL and SQLite backends).
- **codex**: always `false` for now. codex exposes no reliable per-event subagent marker today.
- every other harness: always `false`, since they have no subagent concept.

## Diagnostics

The SDK never writes to stdio. Problems (malformed lines, unreadable files, unusable timestamps) come back as structured `diagnostics`, and skipped source files per harness come back in `skipped`.

Other reader behavior:

- The reader drops zero-token rows regardless of vendor-reported cost.
- Unusable timestamps warn and skip, never epoch-0.
- `calls` aggregation uses the reported count only when finite, else 1 per event.
- Cross-store dedup: the authoritative store suppresses its mirror per harness (OpenCode and zcode SQLite over jsonl, devin CLI SQLite over the Desktop `.ndjson` store, cline's extension store over its CLI session store, deepseek's default JSONL event log over its optional SQLite backend, keyed on `session_id` and `seq`).
- Codex cache-write tokens come from `cache_write_input_tokens` (a 2026-07 protocol addition), a disjoint subset of `input_tokens` like cache reads. The reader subtracts them from input (`input = raw_input - cacheRead - cacheWrite`) and emits them as `tokens.cacheWrite`. Older session files that lack the field count as 0.
